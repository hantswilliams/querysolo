QuerySolo is Apache 2.0 and takes contributions under the Developer Certificate of Origin: sign every commit with `git commit -s`. There is no CLA. The repo is [github.com/hantswilliams/querysolo](https://github.com/hantswilliams/querysolo).

## The repo

| Folder | What |
|---|---|
| `core/` | The Python package `querysolo`: catalog, engine, import, query and history, gauge, questions, CLI, remote tables, API. `uv sync && uv run pytest` here is the whole default check. |
| `build-sessions/` | The build briefs, `core-v0.N-plan.md` (highest N is current), one log per working session, and `TASKS.md`, the running task list. The brief is the authority on what gets built and what its passing test is. |
| `docs/` | The product spec, Day 0 PRD, architecture, build spec, facts and the agent strategy. Where they disagree with the brief, the brief wins. |
| `app/` | The desktop shell: Tauri 2 (Rust) over the core as a sidecar, React and TypeScript in the window. `cargo test` in `app/src-tauri`; `npm run e2e` in `app/` drives the screens in a browser against a real `querysolo serve`. The brief is `build-sessions/app-v0-plan.md`. |
| `web/` | This site, Astro. The docs you are reading are `web/src/content/docs/*.md`; the CLI reference is generated by `web/scripts/gen-cli-reference.py`. |
| `compose.yaml` | Services the default suite does not need: Postgres, RustFS, and an `engines` profile with the catalog, Spark and Trino. |
| `CLAUDE.md`, `AGENTS.md` | Where a coding agent starts. The rules: tests ship with the code, no decisions in code, surgical changes, log the session, keep `TASKS.md` current. |

## The suite

```bash
cd core
uv sync            # once; runtime plus the dev group (pytest, ruff, the S3 mock, dbt)
uv run pytest      # about a minute on a laptop; no Docker, no network after the extensions are cached
uv run ruff check . && uv run ruff format --check .
```

Tests are named for the step of the brief they gate, `tests/test_step<N>_<what>.py`, and every step's gate stays in the suite. Fixtures are generated by the tests that need them; there are no data files in the repo. The timing budgets (the gauge line, the second estimate, startup, query overhead) skip themselves when the one-minute load average exceeds the core count, so they fail only when they can measure.

Some tests need something the default suite does not have and skip without an environment variable:

| Variable | Enables | Needs |
|---|---|---|
| `QUERYSOLO_TEST_PG_URL` | The Postgres variant of the catalog tests | A Postgres; `docker compose up -d --wait postgres`, then `postgresql+psycopg://querysolo:querysolo@127.0.0.1:5433/querysolo` |
| `QUERYSOLO_TEST_S3_ENDPOINT` | The `s3://` tests against a real endpoint instead of the in-process mock | `docker compose up -d --wait s3`, then `http://127.0.0.1:9000` with `AWS_ACCESS_KEY_ID=querysolo AWS_SECRET_ACCESS_KEY=querysoloquerysolo` |
| `QUERYSOLO_PERF=1` | The 200 MB and 2 GB CSV import timings and the ten-thousand-file registration | Time and disk; the registration also needs the `s3` service |
| `QUERYSOLO_TPCH=1` | Strict time accuracy on the TPC-H SF1 harness | Meant for the reference machine; the harness itself runs in the default suite |
| `QUERYSOLO_SMOKE=1` | The engines smoke test: pyiceberg, Spark, Trino and DuckDB each writing to one table through `catalog serve` | `docker compose --profile engines up -d --wait`; the first run fetches Spark's Iceberg jars |

CI runs the suite on macOS and Ubuntu with the four DuckDB extensions cached per DuckDB version, and the Postgres variant against a service container, on every push that touches `core/`.

## The app

```bash
cd app
npm install                                       # Node 22
export QUERYSOLO_SIDECAR=$PWD/../core/.venv/bin/querysolo
QUERYSOLO_PROJECT=~/acme npm run tauri dev          # Rust stable; on Ubuntu also libwebkit2gtk-4.1-dev, librsvg2-dev, libayatana-appindicator3-dev
cd src-tauri && cargo test                        # the supervisor, projects and windows against a fake sidecar
cd .. && npm test && npm run e2e                  # Vitest for the screens; Playwright against real sidecars
```

Each window is one project with one sidecar. The shell spawns `querysolo serve --port 0 -C <project> --memory-limit <n>`, waits for its `serving` line, reads the port and token from `.querysolo/serve.json`, and hands them to the window with the milliseconds that took; the window calls `/api` itself. The limit is 60% of RAM for the first window and half that for each further window open at the same time, so two projects side by side cannot together ask for more than the machine has; closing a window kills its sidecar. Opening a folder without a `querysolo.toml` runs `querysolo init` on it first and shows what it created; the recent ten projects are `recent.json` in the app's data directory. Every action in the window is a CLI verb and shows its exact line with a copy button; `app/src/lib/command.ts` builds those lines and its tests hold them to `querysolo --help`. The query screen posts to `/api/query`, shows the verdict from the response headers before any row, reads the Arrow stream batch by batch into a virtualised grid (100,000 rows at most, then it says so and names `querysolo sql --format parquet`), and Esc aborts the fetch, which interrupts the statement in the core. Screen 2's code (Arrow, CodeMirror) is a separate chunk loaded once there is a table, so the first paint stays inside the launch budget; Vega-Lite, for the auto-chart, loads with the first chart and runs through `vega-interpreter` so the window's content-security policy needs no `unsafe-eval`. The settings panel is `querysolo config set` over `/api/settings`; it rewrites one line of `querysolo.toml` in place. `QUERYSOLO_SIDECAR` names the executable in development; a bundle carries its own (session 10). Under `tauri dev` the window's origin is the Vite server, so the shell passes `QUERYSOLO_DEV_ORIGIN` to the sidecar in debug builds only.

## Making a change

Read `CLAUDE.md` (or `AGENTS.md`), then the current brief's step and its gate. Write the gate as a test first or alongside the code; a change without a test is not done. Anything the brief does not decide is a question for the brief, not a decision in code. New source files carry the two-line header from `core/querysolo/__init__.py`:

```python
# Copyright 2026 QuerySolo contributors
# SPDX-License-Identifier: Apache-2.0
```

No secrets, no partner names, no data files. Keep changes to what the step needs and match the style around them.

## These docs

The docs are markdown under `web/src/content/docs/`, one file per page, with `title`, `description`, `section` (`Start`, `Guide`, `Reference`, `Develop`) and `order` in the front matter. Root-relative links such as `/docs/cli` are rewritten for the site's base path at build time. `web/scripts/gen-cli-reference.py` rewrites `cli.md` from the CLI's help; run it after any CLI change:

```bash
cd web
uv run --project ../core python scripts/gen-cli-reference.py
npm run build
```

The version stamp on every page is read from `core/querysolo/__init__.py` at build time.
