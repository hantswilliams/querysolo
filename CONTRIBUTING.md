# Contributing

QuerySolo is Apache 2.0. Contributions are accepted under the Developer Certificate of Origin (DCO): sign every commit with `git commit -s`, which adds a `Signed-off-by` line certifying you have the right to submit the work. There is no CLA.

- Start from `CLAUDE.md` (or `AGENTS.md`) and the current build brief in `build-sessions/`.
- The core lives in `core/`: `uv sync`, then `uv run pytest`. Every step of the brief ships its test with it; a change without a test is not done.
- The default suite needs no Docker. The Postgres variant of the catalog tests does: `docker compose up -d --wait postgres`, then in `core/` run `QUERYSOLO_TEST_PG_URL=postgresql+psycopg://querysolo:querysolo@127.0.0.1:5433/querysolo uv run pytest tests/test_step1_postgres.py`, then `docker compose down`. CI runs it on every push against a service container.
- Two more opt-in checks live in `compose.yaml`. A self-hosted S3 store (RustFS) for fidelity runs of the `s3://` tests: `docker compose up -d --wait s3`, then `QUERYSOLO_TEST_S3_ENDPOINT=http://127.0.0.1:9000 AWS_ACCESS_KEY_ID=querysolo AWS_SECRET_ACCESS_KEY=querysoloquerysolo uv run pytest tests/test_step1_s3.py`. And the engines smoke test, Spark and Trino reading and writing a QuerySolo table through the catalog: `docker compose --profile engines up -d --wait`, then `QUERYSOLO_SMOKE=1 uv run pytest tests/smoke -s`. Both are skipped without their variables.
- Coding rules: `claude/karpathy.md`. Smallest change that solves the problem; touch only what the task needs.
- New source files carry the two-line Apache header used in `core/querysolo/__init__.py`.
- No secrets, no partner names, no data files in the repo. Fixtures are generated by the tests that need them.
