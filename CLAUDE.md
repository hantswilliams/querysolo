# QuerySolo — instructions for Claude Code

@claude/karpathy.md

## Start here

1. Read `build-sessions/TASKS.md` first: its "Now" names the brief the build is on and which of that brief's steps are built. There are several briefs and the newest is not always the one in play — today it is `ship-v0-plan.md` (the versions round closed 2026-09-17); `core-v0.5-plan.md` is the core's and `app-v0-plan.md` the desktop shell's, both still authoritative for what they cover. Then read that brief. The brief is the authority. Where it conflicts with anything in `docs/`, the brief wins; its §8 lists the edits `docs/` still needs. A decision that belongs to no brief is in `build-sessions/decisions-for-review_<MMDDYY>.md`.
2. Find the step you are on in §4 of the brief. The step's gate is the definition of done for the session. Do not build ahead of it.
3. Read the most recent session log for what happened last time and what is open: `build-sessions/querysolo-build-sessions_<MMDDYY>.md` from 2026-09-30, `build-sessions/lakelet-build-sessions_<MMDDYY>.md` before it (the product was called Lakelet until then; old logs keep their names).

## Rules for every session

- **Tests ship with the code.** Write the step's gate as a pytest test first or alongside the code. It stays in the suite. Report test output as it is; if something fails, say so.
- **No decisions in code.** Anything the brief does not decide goes into a tick-box review block at the top of a new plan revision, not into the implementation.
- **Public style from the first commit.** Apache 2.0 headers, DCO sign-off, no secrets, no partner names, no data files in git. Fixtures are generated by the tests that need them.
- **Surgical changes.** Touch only what the step needs. Match the existing style.
- **Log the session.** One dated file in `build-sessions/` per session: what was built, what the tests showed, what is open.
- **Keep the task list current.** `build-sessions/TASKS.md` is the running list: mark the step you are on, tick gates as their tests pass, and add open items there rather than in prose.

## Repo map

- `build-sessions/` the plans (`core-v0.N-plan.md`; highest N is current) and one log per session
- `docs/` product spec, Day 0 PRD, architecture, build spec, facts, agent strategy; the brief amends them
- `core/` the Python package `querysolo`, created in step 0; `cd core && uv run pytest` runs the suite
- `app/` the desktop shell (Tauri 2, React); `cargo test` in `app/src-tauri`, `npm run e2e` in `app/` against a real sidecar; see `app/README.md`
- `web/` the Astro site; `deck/` and `brand/` are gitignored; `old/` holds retired files
- `compose.yaml` services the default suite does not need: Postgres for the second catalog dialect, RustFS as a self-hosted S3 store, and an opt-in `engines` profile with the catalog, Spark and Trino for the smoke test in `core/tests/smoke/`
- `claude/karpathy.md` the coding rules imported at the top of this file

## Toolchain

uv 0.11, Python 3.13 (package floor 3.12), DuckDB 1.5.x (PyPI serves 1.5.5), pyiceberg 0.12, Moto for the in-process S3 test server, dbt-core 1.12 and dbt-duckdb 1.11 as dev dependencies. Versions and ceilings are in the brief's D15.
